# Docker Guide

The repository's single `Dockerfile` is the supported Cicero build. All targets
use Ubuntu 24.04, Python 3.12, PyTorch 2.13, protobuf 7.35.1, and the patched
ParlAI runtime. The build targets use protoc 35.1; `cuda-runtime` carries the
modules generated by that compiler but intentionally omits the compiler itself.

## Targets

| Target | Description |
|---|---|
| `cpu-build` | Complete CPU development and runtime environment |
| `cpu-test` | CPU environment with the verifier executed during build |
| `cuda-build` | CUDA 13.0 development environment and native build |
| `cuda-runtime` | Smaller CUDA runtime image |

## CPU workflow

```bash
docker build --target cpu-build -t diplomacy-cicero:cpu .
docker run --rm diplomacy-cicero:cpu \
  ./scripts/verify_full_build.sh --accelerator cpu
docker run --rm -it diplomacy-cicero:cpu bash
```

To make verification part of the image build:

```bash
docker build --target cpu-test -t diplomacy-cicero:cpu-test .
```

## Compose workflow

```bash
docker compose build diplomacy
docker compose --profile test run --rm diplomacy_test
docker compose run --rm diplomacy bash
```

The named `diplomacy_models` volume is mounted at `/app/models`. Copy or
download model weights there before running real agents.

## CUDA workflow

The image contains CUDA 13.0 userspace. The Linux host must provide a compatible
NVIDIA driver and NVIDIA Container Toolkit.

```bash
docker build --target cuda-runtime -t diplomacy-cicero:cuda .
docker run --rm --gpus all diplomacy-cicero:cuda \
  ./scripts/verify_full_build.sh --accelerator cuda --require-gpu
```

With Compose:

```bash
docker compose --profile cuda build diplomacy_cuda
docker compose --profile cuda run --rm diplomacy_cuda \
  ./scripts/verify_full_build.sh --accelerator cuda --require-gpu
```

Building `cuda-runtime` without a GPU proves construction and userspace
linkage, not kernel execution. Use the command above on a GPU host or run the
Modal B2/B3 gate.

## Exact build arguments

The defaults are the supported contract:

```text
UBUNTU_VERSION=24.04
PYTHON_VERSION=3.12
TORCH_VERSION=2.13.0
PROTOC_VERSION=35.1
CUDA_VERSION=13.0.3
```

These arguments exist to keep stages aligned, not to advertise a compatibility
matrix. A different value is an unvalidated development experiment.

## Common tasks

```bash
# Regenerate configs and rebuild pydipcc in a development container
make protos
make dipcc

# Supported tests
make test

# Exact runtime contract
./scripts/verify_full_build.sh --accelerator cpu

# Focused engine smoke
python test_pydipcc.py
```

## Troubleshooting

### Docker daemon unavailable

Start Docker Desktop or the Linux Docker service and verify:

```bash
docker info
```

### Build runs out of memory

Reduce native parallelism by building interactively and setting
`N_DIPCC_JOBS`, or allocate more memory to Docker Desktop. Four jobs is the
image default.

### Stale build cache

After changing Python, PyTorch, native dependencies, or generated protobuf
code, rebuild the relevant stage without cache:

```bash
docker build --no-cache --target cpu-build -t diplomacy-cicero:cpu .
```

### GPU is not visible

Check the host before debugging Cicero:

```bash
nvidia-smi
docker run --rm --gpus all \
  nvidia/cuda:13.0.3-cudnn-runtime-ubuntu24.04 nvidia-smi
```

Then rerun `verify_full_build.sh --accelerator cuda --require-gpu`.

### Model files are absent

Images intentionally do not embed the large model tree. Mount a host directory
or use the Compose volume:

```bash
docker run --rm -it --gpus all \
  -v "$PWD/models:/app/models:ro" \
  diplomacy-cicero:cuda bash
```
